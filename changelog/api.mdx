<Update label="SDK Mobile v1.1.1" description="23/09/2026" tags={["SDK", "Tracking", "Novidades"]}>
  ## SDK React Native: atribuição de app

  O [SDK Mobile](/events/mobile) (`@solomon-tech/events-react-native`) ganhou o essencial de
  atribuição de aplicativos, alinhado ao rastreamento web.

  ### Novidades
  - **`APP_INSTALL` / `APP_REINSTALL`** — emitidos automaticamente na primeira abertura após instalar ou
    reinstalar o app.
  - **Identidade durável no iOS** — o identificador do usuário passa a ser guardado de maneira durável,
    sobrevivendo à reinstalação do app.

  ### Mudança de comportamento
  - **`useTouchpoint` agora vem ligado por padrão.** A atribuição funciona ao atualizar, sem configuração
    extra. Para manter o comportamento anterior, defina `useTouchpoint: false` explicitamente.
  - O `referrer` dos eventos deixou de carregar o nome da tela interna do app, evitando poluir o canal
    **Orgânico**. A atribuição continua vindo por `utm_*` / `sol_*`.

  ### Atualização
  ```bash Terminal
  npm install @solomon-tech/events-react-native@1.1.1
  ```
  Para identidade durável no iOS, instale a dependência opcional e rode os pods:
  ```bash Terminal
  npm install react-native-keychain && cd ios && pod install && cd ..
  ```

  Veja o guia do [SDK Mobile](/events/mobile).
</Update>

<Update label="Admin API v1.1.1" description="23/09/2026" tags={["API", "Novidades"]}>
  ## Pedidos de assinatura

  Novo campo `subscription` no pedido para identificar pedidos de assinatura e distinguir a
  **aquisição** (primeiro pedido da assinatura) da **renovação** (cobrança recorrente).

  ### Novo campo de pedido
  - `subscription` (objeto, opcional) — presente apenas em pedidos de assinatura; **omita** o objeto para pedidos avulsos.
  - `subscription.isRecurring` (boolean, obrigatório quando `subscription` é enviado):
    - `false` — primeiro pedido da assinatura (aquisição)
    - `true` — renovação (cobrança recorrente)

  ### Comportamento
  - Independe de `isFirstOrder`: a aquisição de uma assinatura só entra em **Vendas (NC)** quando também for o primeiro pedido do cliente (`isFirstOrder: true`).
  - Uma renovação (`isRecurring: true`) **não pode** vir com `isFirstOrder: true`.
  - Retrocompatível: omitir `subscription` mantém o comportamento atual.

  Veja [Pedidos](/store/orders).
</Update>

<Update label="Admin API v1.1.0" description="03/09/2026" tags={["API", "Novidades"]}>
  ## Custos adicionais, influenciadores e novos campos de pedido

  Esta versão expande a Admin API para cobrir, via API, o que antes só era gerido pelo dashboard.

  ### Custos adicionais
  CRUD completo de custos manuais da operação (aluguel, plataformas, marketing, etc.):
  - `GET /costs` — lista os custos agrupados por frequência
  - `POST /costs` — cria um custo
  - `PUT /costs` — edita um custo
  - `DELETE /costs` — remove um custo
  - `GET /costs/historical` — histórico diário projetado

  Veja o guia de [Custos adicionais](/management/costs).

  ### Influenciadores
  Cadastro e gestão de influenciadores, campanhas, links, cupons e custos de comissão:
  - `GET /influencers`, `POST /influencers`, `PUT /influencers`, `DELETE /influencers`
  - `GET /influencers/costs`, `POST /influencers/costs`, `DELETE /influencers/costs`
  - `POST /influencers/coupons`, `DELETE /influencers/coupons`

  Os links são encurtados e instrumentados com UTMs pela Solomon, e as URLs passam por validação de
  segurança (HTTPS + host público). Veja o guia de [Influenciadores](/management/influencers).

  ### Novos campos de pedido
  - `isFirstOrder` (pedido) — indica explicitamente o primeiro pedido do cliente.
  - `customer.birthdate` — data de nascimento do cliente (ISO `YYYY-MM-DD`).

  Ambos são opcionais e retrocompatíveis. Veja [Pedidos](/store/orders).

  ### Novos escopos
  Foram adicionados os escopos `costs.read`, `costs.write`, `influencers.read` e `influencers.write`.
  Gere ou atualize sua [API Key](/authentication) concedendo apenas os escopos necessários.
</Update>
